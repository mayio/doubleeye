# Writing rules

Every one of these thirteen rules was written after getting it wrong somewhere in this
repository or in the published posts. The mechanical half is enforced by `tools/doccheck.py`; the rest
is judgement, and the failure that produced each rule is named so the judgement has
something to stand on.

```bash
tools/doccheck.py                 # doc/, CLAUDE.md, article/
tools/doccheck.py --blog          # also the posts and the glossary
tools/doccheck.py --self-test     # prove the checker can still fail
```

Applies to `doc/`, `CLAUDE.md`, source comments, commit messages, and the published
posts. Where a rule is only about the posts it says so.

---

## 1. A number without its context is not a measurement

State the machine, the input, the configuration and the unit **in the sentence that
carries the number**. A reader must never have to guess which of those a figure
belongs to, and a number lifted into another document must carry them with it.

*Produced by:* a desktop timing quoted against the Jetson's frame budget, wrong by 3×,
and every ratio later scaled from it (obstacles 15 and 22). Also by two rate tables
that both said "31.7 ms" while meaning different disparity ranges.

## 2. The same quantity uses the same unit in every document

Pick one basis and say it. If a figure depends on a parameter, give the parameter.

*Produced by:* the cost volume, quoted as 98 MB in Part 2 and 49 MB in Part 3. Both
were right — one was float, the other int16 — and together they were unreadable.
Neither said which, and neither said at what `D`.

## 3. Cite the measurement, or say it is untested

Both are fine. Asserting is not. A justification in a comment is a claim, and the
claims in comments are the ones that turn out wrong.

*Produced by:* the QoS comment that stated the opposite of how DDS compatibility
works; the local-contrast intuition, which predicts correctness *negatively*; the
ordering factor, whose sign flipped twice before it was measured over seeds.

## 4. Documentation describes the present, never the change

No "update", "previously", "now changed", "as before". A document is what is true
today, written as though it had always said that. History lives in git and in
[03-obstacles.md](03-obstacles.md), which is the one file allowed to be chronological.

The reason is not tidiness. A document written as a sequence of updates forces every
reader to reconstruct the past to find the present, and it decays the moment one
update is missed.

## 5. A retired value is hunted, not left

When a default changes, grep every document for the old value before committing, and
add the retirement to `RETIRED` in `tools/doccheck.py` so it stays caught.

*Produced by:* `D=60` surviving in a rate table, a figure, a glossary entry and two
posts after the default became 64; and `--min-range 0.4` outliving the measurement
that replaced it.

## 6. Name a section, link the section — and verify the link mechanically

Any cross-reference by name gets a link. Anchors are generated by a tool, so check
them against **what that tool actually emits**, not against what its documentation
implies.

A link that resolves can still be wrong, so `doccheck.py` checks three further
things. A reference naming a number — `section 4.2`, `§7`, `Part 2` — must point at
that number. And a link's text must share a word with the heading or opening lines of
what it points at, or match it by acronym, or name an author who appears in the entry.
A link text that shares nothing with its target is either aimed at the wrong place or
too vague to tell which.

*Produced by:* Part 2 citing the intrinsic-curves result as "section 8" for weeks, with
a working link to section 9. And by nearly shipping a set of anchors built from stock
kramdown's rule, which strips leading digits from a heading id. The site sets
`input: GFM`, whose slugger keeps them. The published HTML settled it in one request;
reasoning about it would have produced a page of dead links.

## 7. A negative result is recorded with its mechanism

Not "we tried X and it did not help" but why, in enough detail that the next person
can tell whether their situation differs. A knob left in the code is worse than a
paragraph explaining why it was removed.

*Produced by:* local contrast, the coarse-to-fine pass, the cheap smoothness prior and
cheaper misdetection — all documented as not working, all still not retried.

## 8. Code in a document must run, and must be checked against the shipping code

If a document shows an algorithm, the snippet is executable and its output is compared
against the real implementation. State the agreement.

*Produced by:* the NumPy transcription of the edge-aware filter in Part 2. Writing the
check found the detail the prose would otherwise have got wrong — invalid entries are
filled with `0` before filtering, not left at the sentinel the dump uses, because the
recurrence propagates whatever it finds in the border into the valid window. The first
version disagreed with the C++ by 10²⁹.

## 9. Figures are generated, never drawn by hand

One script, run against the shipping binary, so a figure cannot drift from the code.
Then check, by looking at the image:

- every text box holds its text, with nothing overflowing or overlapping;
- every axis carries a unit;
- numbers in a figure and numbers in the surrounding table agree **as printed** — if
  one rounds 41.5 to 42 and the other to 41, spell both out;
- if an example was selected from many, the caption says by what rule.

*Produced by:* four figures whose labels overflowed their boxes, one whose MB figures
predated a default change, and a bar chart that rounded the frame rate differently
from the table beside it.

## 10. Write for an engineer whose first language is not English

- One idea per sentence. Split anything past about thirty words.
- No idioms, no metaphors: not *earns its keep*, *rides along for free*, *is a wash*,
  *ate it*, *bolted on*, *eat into*, *made the question moot*.
- Put the subject first and keep the verb near it.
- Expand an abbreviation the first time it appears, every document.
- Prefer the plain word: *use* over *leverage*, *about* over *on the order of*.

Precision is not the same as density. Nothing here asks for less detail — it asks for
the same detail in shorter sentences.

## 11. A statement about a default says what the default asserts about the world

`--min-range 0.4` is not a number, it is the claim "nothing in this scene is nearer
than 0.4 m". Write the claim, so a reader can notice it is false for them.

## 12. Show the mathematics, a worked example, or the code

Whenever one of the three explains something faster than prose, use it. They are not
decoration and they are not for experts only. A formula is usually the shortest
unambiguous statement available, and a reader whose first language is not English can
read one without translating it.

- **Write the equation** rather than describing it. "A parabola through the winner and
  its two neighbours" is four lines of prose in place of one line of algebra, and it
  leaves the reader unable to reproduce the result.
- **Give the numbers for the shipping values.** An equation in symbols says what a knob
  does; the same equation evaluated at the shipping setting says what the knob *is*.
  Write both.
- **Show the code when the algorithm is short**, and check it against the shipping
  implementation (rule 8). Fifteen lines of NumPy carried the edge-aware filter that
  three documents had been calling "aggregate the volume".
- **Prefer a worked example with real numbers** to a description of what would happen.

*Produced by:* the aggregation stage, which appeared in three documents and two posts
without any of them saying what it computes; and the two sub-pixel estimators, chosen
between on the strength of a 0.71-point measurement and described for months as "a
parabola" and "the equiangular one", with neither formula written down.

## 13. Before trusting a check, make it fail once

This applies to the documentation tooling as much as to the matcher.
`tools/doccheck.py --self-test` builds a document containing one instance of every
fault and asserts that every check fires. If a check cannot be made to fail, it is not
evidence.

*Also produced by:* the first version of that self-test, which handed the link checker
an empty set of targets. Two of its three reference checks fired, and the third could
not have fired for any input at all.

*Produced by:* a frame-gap check that reported `0 missing` while a third of frames were
lost, and a link checker of mine that reported one false break and would have reported
none at all if its anchor rule had been wrong in the other direction.
